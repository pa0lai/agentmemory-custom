## 摘要

LLM 後訓練 (post-training) 中一個流行的敘事是：監督式微調 (Supervised Fine-Tuning, SFT) 會記憶 (memorize)，而強化學習 (Reinforcement Learning, RL) 會泛化。我們在帶有 long chain-of-thought (CoT) 監督訊號的推理 SFT 上重新檢視這個論點，發現跨領域 (cross-domain) 泛化並非缺席，而是 *條件式* 的——同時被三個因素形塑：**最佳化動態 (optimization dynamics)、訓練資料 (training data)，以及基底模型能力 (base-model capability)**。

一些被報告為「不泛化」的失敗其實是 *under-optimization* 的偽影 (artifact)：跨領域效能會先 *退步*，再 *恢復*，並隨著訓練延長而 *提升*（一個 *dip-and-recovery* 的型態）。所以短訓練的檢查點可能會嚴重低估泛化潛能。資料品質與結構也很關鍵：低品質解答會壓低跨領域泛化，而經過驗證的 long-CoT 軌跡能帶來穩定的跨領域增益。模型能力很重要：較強的基底模型會把可遷移的程序模式 (transferable procedural patterns)（例如 backtracking）內化下來，即使是來自一個玩具算術遊戲的訓練資料；較弱的模型則仍停留在模仿表層詞彙 (surface-level verbosity) 的階段，造成泛化不佳。

不過這個泛化是 *不對稱* 的：推理改進的同時，**安全性 (safety) 退化**。所以問題就從「推理 SFT *是否* 泛化」改寫為「在 *什麼條件下* 泛化、以及付出 *什麼代價*」。

## 1. 引言 (Introduction)

LLM 後訓練中一個流行的敘事是：SFT 改善 in-domain 效能但容易記憶；RL 則泛化得比較好。Chu et al. (2025) 在合成任務上建立了具影響力的「SFT memorizes, RL generalizes」框架，後續工作在更實際的設定（例如數學推理）也回報了類似結果 (Huan et al., 2025)。這個敘事推動了大量強調 RL 優於 SFT 的研究 (Chen et al., 2025; Shenfeld et al., 2026; Lai et al., 2026; Zhu et al., 2025)，以及對 SFT 目標本身的演算法修改 (Wu et al., 2026; Zhu et al., 2026)。

然而支撐這個敘事的實驗條件其實有相當大的差異。例如 Chu et al. (2025) 的訓練沒有 long CoT 監督；Huan et al. (2025) 訓練的 epoch 數很少；許多研究受運算或時間限制，使用了較小或早期世代的基底模型，且明確認為模型能力是個因子。另外，許多 SFT-vs-RL 比較聚焦在 *retention*（微調是否會降低既有能力），而非 *acquisition*（新泛化能力是否被獲得），且常常從 instruction-tuned 模型開始——這會混淆對齊與微調差異 (Chen et al., 2025; Lai et al., 2026)。最佳化、資料、模型能力與起點檢查點上的這些 *糾纏 (entangled)* 差異，使得我們很難分辨報告的「泛化失敗」是 SFT 本身的內在屬性，還是只是特定實驗條件的偽影。

這個問題對 *推理 SFT* 特別迫切——這類訓練常用 long CoT 軌跡。Long-CoT 軌跡在資料結構上和短回答目標不同，更難 fit 進去，對模型能力的需求也更高。這讓推理 SFT 的最佳化、資料、模型因素都更關鍵、也更值得清楚研究。

在這篇工作中，我們證明推理 SFT 的泛化 *不是* 訓練目標自身的內在屬性，而是一個 *條件式現象 (conditional phenomenon)*，由 **最佳化動態、訓練資料、模型能力** 共同形塑。我們系統性地一次只變動一個因子來識別 *何時* 與 *如何* 推理 SFT 在不同領域上能泛化，以及隨之而來的取捨。我們採用「在預訓練的基底模型上做純數學推理 SFT」作為實驗台 (testbed)，這個設定提供容易驗證的回應，並能與先前研究 (Huan et al., 2025; Wu et al., 2026) 直接比較。然後我們在 in-domain 數學推理、OOD (out-of-distribution) 推理（程式、數學、科學）、一般能力（指令遵循等）與安全性上評估泛化。我們的發現如下：

![圖 1](/assets/2604.06628v1/figure1.png)

**圖 1.** 概念框架：推理 SFT 中的泛化是一個由最佳化動態、訓練資料與模型能力共同形塑的條件式屬性。

- **「表面上的不泛化」可能只是 under-optimization 偽影。** 泛化效能在 long-CoT SFT 訓練過程中呈現一個 *dip-and-recovery* 型態：先退步、之後再恢復、最終超過基底模型，這意味著短訓練的檢查點會系統性低估 SFT 的泛化潛力。進一步分析顯示，long-CoT 資料受益於 *重複曝光 (repeated exposure)* 多過於 *單次 pass* 的 matched compute；明顯的過擬合 (overfitting) 症狀只在激進的訓練排程下才出現。這意味著在這個情境下，*under-optimization 比 over-optimization 更可能成為主要風險*。
- **訓練資料對泛化很重要。** 資料品質很關鍵：在低品質解答上做 SFT 會普遍傷害效能，而經過驗證的 long-CoT 軌跡能帶來穩定的跨領域增益。資料 *結構* 也重要：在強的基底模型上，來自玩具算術遊戲（**Countdown**）的 long-CoT 軌跡能改善多個推理 benchmark，甚至能贏過一個內容多元的數學資料集（不含 CoT）。這暗示 *程序模式 (procedural patterns)*（例如 backtracking 與 verification）可能比領域內容本身更能驅動泛化。
- **泛化需要足夠的模型能力。** 在相同的 long-CoT 資料下，較強的基底模型在多個領域上展現廣泛的泛化，較弱的模型則只在 in-domain 數學上有微小或負面的增益，並且只產出「拉長的回應」(prolonged responses)。這暗示較弱的模型可能只是模仿推理的 *表層形式*（例如冗長），而沒有內化驅動跨領域增益的模式。
- **泛化是不對稱的。** 儘管獲得廣泛增益，long-CoT SFT 會削弱安全性 (safety)，與先前在推理模型中關於 self-jailbreaking 的觀察一致 (Yong & Bach, 2025; Mao et al., 2025)。訓練後，模型在思考過程中會把自己合理化（例如「為了教育目的」），最終生成有害內容。在我們的對照比較中，CoT 帶來的安全下降比 no-CoT 大得多，這顯示這個劣化是被 *程序模式* 驅動，而非 *領域內容*。

這些結果暗示「SFT 是否泛化？」這個問題本身就被低度規範 (under-specified)。泛化不是 SFT 目標的一個固定屬性，而是會隨最佳化充足度、資料品質與結構，以及基底模型能力而大幅改變。當這些因素中任何一個不齊全時（例如 evaluating 早期 checkpoint、用低品質資料訓練、或使用弱基底模型），所做的結論就可能把 *特定實驗設定的偽影* 誤認為 SFT 的內在限制。一個更具生產力的框架是：**問「在什麼條件下」推理 SFT 會泛化**，我們的研究是邁向繪製這個條件式 landscape 的早期一步。

## 2. 實驗設定

這一節描述預設的實驗設定。具體變動會在後面相關章節中介紹。

### 2.1 模型、資料集與訓練協議

我們的主實驗使用 **Qwen3-14B-Base** 與 **Qwen3-8B-Base** (Yang et al., 2025) 作為基底模型，並包含 **InternLM2.5-20B-Base** (Cai et al., 2024)、**Qwen2.5 base 模型** (Yang et al., 2024) 來確認觀察的趨勢能延伸到不只一個模型族系。所有這些模型都是預訓練後尚未做過任何對齊或偏好最佳化的檢查點，這能最小化來自對齊的混淆。後面章節還會檢視小一點的模型（例如 4B 與 1.7B）來研究模型能力的角色（第 5 節）。

我們的預設訓練資料集 **Math-CoT-20k** 由 20,480 個帶 long CoT 的數學推理範例組成。query 從 OpenR1-Math-220k (Lozhkov et al., 2025) 的預設子集取樣，回應由 Qwen3-32B 在開啟 thinking 模式下產生。每個回應包含一個 thinking 過程，後面接著 step-by-step 的最終總結與答案。我們在每個 query 用 math-verify (Hugging Face, 2024) 產生多個帶正確答案的回應。最大回應長度設為 16,384 tokens。完整資料生成設定請見 App. B.1。

除非另有說明，所有模型都是用標準 SFT objective 訓練（最小化 negative log-likelihood over response tokens）。預設訓練排程使用 **AdamW optimizer**、學習率 (learning rate) **5e-5**、batch size **256**、cosine learning rate schedule、與 8 個訓練 epochs。這些選擇會在第 3 節被系統性地變動以研究最佳化動態的角色。更多最佳化細節見 App. B.2。

### 2.2 評估套件

我們的評估套件目標是同時捕捉推理 SFT 的潛在好處與成本：

- **In-domain (ID) 推理**：MATH500 (Hendrycks et al., 2021) 與 AIME24 (Math-AI Team, 2024)，直接對齊訓練領域。
- **Out-of-domain (OOD) 推理**：LiveCodeBench (LCB) v2 (Jain et al., 2025) 評估 coding；GPQA-Diamond (Rein et al., 2024) 評估研究所等級科學推理；MMLU-Pro (Wang et al., 2024) 評估廣泛的知識密集推理。這些任務需要不存在於訓練資料中的領域上的推理能力。
- **一般能力**：IFEval (Zhou et al., 2023) 衡量指令遵循正確率；AlpacaEval 2.0 (Li et al., 2024; Dubois et al., 2024) 衡量開放式回應品質；HaluEval (Li et al., 2023a) 與 TruthfulQA (Lin et al., 2022) 衡量真實性 (truthfulness)。這些 benchmark 測試推理 SFT 是否會增強、或干擾更廣的模型行為。
- **安全性**：HEx-PHI (Qi et al., 2024) 評估模型對有害 query 的抵抗能力，透過攻擊成功率 (Attack Success Rate, ASR) 與 harmfulness score 衡量。

預設情況下，我們用 temperature 0.6、最大生成長度 32,768 tokens 來解碼。MATH500、GPQA-Diamond 用 avg@3、AIME24 用 avg@10、IFEval/HaluEval/MMLU-Pro 用 pass@1 報告分數。對於 IFEval 我們用嚴格的 instruction-level 正確率。對 AlpacaEval 2.0 用 `Llama-3.1-8B-Instruct-RM-RB2` reward model 平均分。對 TruthfulQA 用官方 judge model 評分 helpfulness 與 truthfulness。對 HEx-PHI，沿用原論文用 GPT-4.1 作為 judge model；分數 5 視為一次成功的攻擊。所有評估都是 zero-shot 進行。完整評估細節見 App. B.3。

## 3. 推理 SFT 的最佳化動態

先前研究的常見結論是「SFT 改善 in-domain 效能但對 OOD 任務泛化不佳，甚至會惡化 OOD 能力 (Chu et al., 2025; Huan et al., 2025)」。在這一節，我們證明這個結論有時是 *對訓練軌跡的不完整觀察* 的結果：long-CoT 推理資料比短回答目標更難內化，而從基底模型到「訓練良好的推理模型」這條路會經歷一些容易誤讀的非平凡動態。

### 3.1 「表面上的不泛化」可能是 under-optimization 偽影

**先前發現的複現。** 我們先在同樣的 short-epoch 協議下複現 (Huan et al., 2025) 的弱跨領域泛化結果：在 Math-CoT-20k 上訓練 Qwen3-14B-Base 一個 epoch。如圖 2 所示，in-domain 數學表現大幅改善，而 OOD 增益在某些 benchmark（例如 LCB v2、GPQA-D）上有限，並且在另一些（例如 IFEval、AlpacaEval）上甚至變成負的。這種弱泛化在較小學習率下更明顯（App. C.1）。

![圖 2](/assets/2604.06628v1/figure2.png)

**圖 2.** 複現先前發現：短 epoch 推理 SFT 大幅改善數學，但對 OOD 推理與一般能力只產生有限或負面增益。

**跨領域泛化會非單調 (non-monotonically) 演化。** 我們接著把訓練 epoch 數延長到 8（我們的預設設定），並追蹤 Qwen3-14B/8B-Base 與 InternLM2.5-20B-Base 在訓練全程的 benchmark 效能。圖 3 (top) 顯示效能隨訓練 step 的變化，呈現一個明顯的 *dip-and-recovery* 型態。在 in-domain 數學推理任務（MATH500、AIME24）上，效能呈現一個短暫的早期 dip 後快速恢復¹，然後是一個清楚的上升趨勢。多個 OOD benchmark（例如 LCB v2、GPQA、IFEval、AlpacaEval 2.0）展示類似的型態：通常是 *更深的 dip + 較慢的 recovery*，但在延長訓練後最終會超過基底模型水準。

![圖 3](/assets/2604.06628v1/figure3.png)

**圖 3.** Long-CoT 推理 SFT 的訓練動態。**Top**：benchmark 效能隨訓練 step 的變化，在大多數 benchmark 上呈現共同的 *dip-and-recovery* 型態。**Bottom**：response length 隨訓練 step 的變化，早期 length surge 後逐漸 pullback 到較短回應。

這個型態並非單一 teacher 模型獨有：用 DeepSeek-R1 產生的回應重複同樣的設定（同樣的 20k 數學 query），結果類似，只有 absolute 分數有些微差異（App. C.2）。這些觀察暗示一些 *先前回報的 SFT 泛化限制*，其實可能是 *under-optimization* 的偽影，而非 SFT 自身的內在限制。它們也意味著 long-CoT 資料是 optimization-challenging 的，需要延長訓練、且呈現微妙的動態。

> ¹ 如第 4、5 節將會展示的，這個 recovery 也取決於 *資料品質與模型能力*。

### 3.2 把 response length 當作最佳化進度的診斷指標

為了更好地理解 dip-and-recovery 動態，我們追蹤 response length 隨檢查點的變化，並與效能比較。如圖 3 (bottom)，response length 在早期訓練快速上升、之後逐漸下降。這個 *rise-and-fall* 趨勢經常與效能變化共現：最長的回應傾向出現在效能最弱時，當效能恢復後回應變得更精簡。

**詮釋。** 在 long-CoT SFT 早期，模型先學到一個顯著的表層模式：它們產出延長的「思考形式」軌跡，然後才可靠地學到更細的推理模式（例如分解、backtracking、self-evaluation；見 App. C.3）。這個階段傷害效能有兩個方式：(1) 對 long CoT 的 *淺層模仿* 限制了推理任務上的遷移；(2) 冗長的輸出加上偶爾的格式錯誤（例如缺失 `</think>` tag）會影響指令遵循與對齊。隨著 optimization 的繼續，模型學到 *更可遷移的程序模式* 與 *更精細的語言風格*，產出更短、更精準的輸出，以及更強的跨領域泛化。

因此 response length 是 long-CoT SFT 中最佳化進度的 *粗略但實用的診斷指標*：回應仍在縮短的檢查點通常還沒被充分最佳化，即使 in-domain 表現看起來已經合理。

### 3.3 為什麼更長訓練有幫助：重複曝光還是更多 step？

**設定。** 跑 long-CoT 資料的擬合難度自然引出一個問題：在小資料集上跑多個 epoch 比較有效，還是在大資料集上跑一個 epoch 比較有效？我們設計了一個對照實驗，三個設定全部用 Qwen3-14B-Base、固定總 gradient step 數（640 步）：**Setting 1**（預設，20k 範例、batch 256、8 epoch）、**Setting 2**（2.5k 範例、batch 32、8 epoch、cosine LR）、**Setting 3**（20k 範例、batch 32、1 epoch）。Setting 2 與 Setting 3 之間的關鍵比較是它們有匹配的訓練預算 (training budget)，但 *曝光模式不同*（8-pass repetition 對 1-pass coverage）。

![表 1](/assets/2604.06628v1/table1.png)

### 3.4 從 underfitting 到 overfitting：症狀與機制

**設定。** 上面的結果暗示在我們預設的 long-CoT 設定中，underfitting 訊號比 overfitting 更明顯。為了關閉這個迴圈，我們在 Qwen3-14B-Base 上 *壓力測試 (stress-test)* 訓練激進度——四個排程：**Setting 1**（預設，LR 5e-5、8 epoch、cosine LR schedule）、**Setting 2**（LR 5e-5、16 epoch、cosine LR）、**Setting 3**（LR 5e-5、16 epoch、constant LR）、**Setting 4**（LR 1e-4、16 epoch、constant LR）。這些設定逐步增加最佳化強度，從輕度到激進。

**Overfitting 症狀與 regime。** 如圖 4 (top) 所示，在所有激進設定下，Setting 2 在訓練全程都維持穩定效能或繼續改善。Setting 3 在部分 OOD 套件上開始呈現後期 degradation。Setting 4 顯示最清楚的 overfitting 型態：OOD 效能廣泛下降，甚至連 in-domain 數學表現都退化，而 response length 開始重新上升（圖 4 bottom）。

![圖 4](/assets/2604.06628v1/figure4.png)

**圖 4.** Benchmark 效能（**top**）與 response length（**bottom**）在 overfitting stress test 不同訓練 step 上的變化。其他 benchmark 結果見 App. C.4。

因此，在我們的設定中，明顯的 overfitting 症狀主要出現在 *組合式的激進排程*（高學習率、無 LR decay、長 epoch）下，通常伴隨廣泛的效能下降（包括 in-domain 數學）與 response length 的反彈。

## 4. 訓練資料如何形塑泛化

第 3 節證明充分訓練的推理 SFT 能跨領域泛化。這裡我們證明這個泛化 *關鍵地* 取決於訓練資料的品質與結構。

**設定。** 我們在預設訓練設定下比較四個資料配置。除了預設的 Math-CoT-20k 之外，引入三個變體：

- **Math-NoCoT-20k**：去掉 `<think>...</think>` 的 Math-CoT-20k，只保留最終 step-by-step 摘要與答案。
- **NuminaMath-20k**：從 NuminaMath-1.5 (Li et al., 2024) 取樣的 20k 範例，使用同樣的 query 與 Math-CoT-20k 一致，但用人類撰寫的解答、無 long CoT。解答通常較短、品質混雜（例如缺少 step），常被先前 SFT 泛化研究使用 (Wu et al., 2026; Zhang et al., 2026)。
- **Countdown-CoT-20k**：來自 Countdown-Tasks-3to4-Unique 的 20k Countdown (Pan et al., 2025) 範例，搭配 Qwen3-32B 生成的 long-CoT 回應。Countdown 是一個簡單算術遊戲，需要 trial-and-error。

**Long-CoT 軌跡的角色。** 比較 Math-CoT-20k 與 Math-NoCoT-20k 把 long CoT 軌跡的影響隔離出來：兩個變體共享同樣的 query 與最終 step-by-step 解答，而 Math-NoCoT-20k 省略探索性的 thinking。

表 2 顯示 long-CoT 監督在 *推理密集任務上產生更強的泛化*，特別在 in-domain 數學推理上。對 OOD 推理任務（LCB v2、GPQA-D、MMLU-Pro），同樣的趨勢在較大模型上仍可見，而較小的 Qwen3-8B 模型上 gain 較弱。相反地，對 IFEval 與 AlpacaEval 2.0，Math-NoCoT-20k 表現常常略好——因為這些 benchmark 強調 instruction following 與 alignment 相關行為，而非原始推理。

![表 2](/assets/2604.06628v1/table2.png)

**表 2.** 四個資料配置之間的效能比較。每個 model block 內最佳/次佳以粗體/底線標示。我們報告最後檢查點的效能。

**資料品質很重要。** 在 no-long-CoT 設定下，我們進一步比較 Math-NoCoT-20k 與 NuminaMath-20k 來隔離資料品質的影響。表 2 顯示 Math-NoCoT-20k 持續表現得更好，而 NuminaMath-20k 則展示廣泛的 OOD degradation 與在 in-domain 數學推理上幾乎沒有 gain。此外，Tab. 20 顯示 NuminaMath 在第 3 節的 dip-and-recovery 動態裡幾乎沒有 recovery。這意味著 *低品質資料能顯著降低 SFT 的效用*，而在低品質資料上訓練可能造成「SFT 不泛化」的錯誤印象。

**程序泛化：來自 Countdown 的證據。** Countdown-CoT 資料測試 long-CoT SFT 是否能 *把抽象推理程序遷移* 到領域特定知識之外。它是一個算術遊戲，模型必須用一組數字加上基本運算 (+, −, ×, ÷) 來達成目標值。Countdown-CoT 中的 response trace 包含了結構化的探索程序，例如 *分解 (decomposition)、backtracking、與 verification*，但沒有顯式的領域知識。

表 2 顯示在兩個 Qwen3 模型上，Countdown-CoT-20k 在數學任務上比 base 還強，儘管 Math-NoCoT-20k 在數學任務上的 narrow scope 更狹窄。這暗示 *推理程序的結構*——而非領域內容——能成為泛化的關鍵驅動力。然而這個結論並非普遍成立：在 InternLM2.5-20B 上，Countdown-CoT 在數學任務上只有 marginal 增益，這意味著程序泛化的有效性也取決於 *基底模型能力*（我們在第 5 節檢視這個因子）。此外，Countdown 並沒有對所有任務同等泛化——例如 IFEval 分數會劣化。

## 5. 模型能力如何影響泛化

前面章節證明泛化取決於最佳化動態與訓練資料。在這一節，我們檢視第三個因子：基底模型能力。我們證明同樣的訓練資料與訓練協議能在不同模型規模下產生 *非常不同* 的泛化結果。

**設定。** 我們在同樣的 Math-CoT-20k 資料、同樣的訓練協議下，訓練四個尺寸遞增的 Qwen3 base 模型：1.7B、4B、8B、14B。在這個對照設定中，泛化行為的差異可以歸因於模型能力的差異。

**能力越高的模型泛化越好。** 圖 5 顯示一個清楚的、能力相關的趨勢：14B 模型展示明顯的 dip-and-recovery 軌跡，並在多個領域上以廣泛 gain 結束。8B 與 4B 模型也展示一個 recovery 階段，且伴隨較小的改進，而 1.7B 模型在所有 benchmark 上都呈現 marginal 或負面 gain，即使在後期檢查點。這個型態暗示 optimization 與 data 並不能單獨保證泛化：能力較高的模型更可能 *內化可遷移的推理模式*，而能力較低的模型則傾向 *模仿表層形式*。這個結果暗示 §3.1 的 dip-and-recovery 動態本身也取決於模型能力。其餘 benchmark 與 Qwen2.5 的結果見 App. C.5。

![圖 5](/assets/2604.06628v1/figure5.png)

**圖 5.** 跨模型尺寸的效能（**top**）與 response length（**bottom**）比較。較大的模型展現更強的跨領域泛化與更短的回應長度。

**Response length 與模型能力。** 圖 5 也顯示較小的模型在延長訓練後仍維持較長的回應，而較大模型的回應長度下降得更快、穩定在較低值。如 §3.2 所討論，response length 可被當作學習階段的粗略診斷指標：仍卡在 prolonged-response 階段的模型可能尚未進步到表層詞彙之外。較小的模型更可能停留在這個階段，這意味著有限的能力會延後從模仿 long-response 模式進入內化真正推理模式的轉變（見 App. C.6 與 C.7 的 case study 與分析）。這也呼應了先前的觀察：小型 distilled reasoning 模型（例如 Deepseek-Distill-Qwen-1.5B）的回應通常比大型 distilled 對應物（7B 與 14B）更長 (Guo et al., 2025)。

## 6. 不對稱泛化：long-CoT SFT 下的安全性

前面章節證明 long-CoT 推理 SFT 能跨領域遷移。然而這個遷移是 *不對稱的*：同樣的訓練持續削弱 *安全性* 與 *拒絕* 能力。配合 matched query 與 final answer 的 CoT vs. no-CoT 對照進一步暗示這個劣化來自 long-CoT 軌跡中的 *程序模式*。

**設定。** 我們在三個基底模型（Qwen3-14B-Base、Qwen3-8B-Base、InternLM2.5-20B-Base）上評估 HEx-PHI 的安全性效能。具體來說，我們把 base model 與在 Math-CoT-20k 與 Math-NoCoT-20k 上做 SFT 的檢查點做比較。

![圖 6](/assets/2604.06628v1/figure6.png)

**圖 6.** (a) 三個訓練檢查點上的 Attack Success Rate (ASR；越低越安全)。(b) Case study：long-CoT SFT 後的模型在 thinking 過程中傾向自我合理化 (self-rationalize)，最終產生有害內容。

**Long-CoT SFT 下的安全性退化。** 圖 6(a) 顯示用 long-CoT 資料 (Math-CoT-20k) 訓練在三個模型上都導致 ASR 大幅上升。相對地，在 no-CoT 資料 (Math-NoCoT-20k) 上訓練則只造成小很多的安全退化。由於 Math-CoT-20k 與 Math-NoCoT-20k 包含同樣的 query 與最終解答，這暗示觀察到的安全下降與 long-CoT 軌跡中的 *程序模式* 比和數學內容更有關。

**Long-CoT SFT 如何改變拒絕行為：a case study。** 為了理解這個劣化，我們比較了模型在 long-CoT SFT 前後對同樣有害 query 的回答（圖 6 (b)）。Base model 經常直接拒絕。在 long-CoT SFT 之後，模型一開始有警告，但在 thinking 過程中 *自我合理化*（例如「為了教育目的」），最後提供包裝在 caveat 中的有害細節。

*矛盾地，這也可能是一種「泛化」的形式*。我們推測 long-CoT 推理會強化一個 *持久的問題解決態度*：探索替代方案、搜尋可行路徑、堅持穿越障礙。對有害 query 而言，*障礙就變成了拒絕政策本身*，而延長推理就提供了空間去繞過 safety guardrail。

## 7. 相關研究

**SFT 與 RL 的比較** 在後訓練中得到許多關注。Chu et al. (2025) 在合成任務上建立了具影響力的「SFT memorizes, RL generalizes」框架。最相關的是 Huan et al. (2025)，他們在同樣的 short-training 協議下評估 long-CoT 數學 SFT 的跨領域可遷移性，發現有限的 gain——這個發現我們也在同樣的 short-training 協議下複現了，但延長最佳化後得到 *質性上不同* 的結果。一個密切相關的工作系列研究 RL 相對於 SFT 的優勢，歸因於 reduced forgetting 或既有能力的恢復 (Chen et al., 2025)、mode-seeking updates toward KL-minimal policies (Tajwar et al., 2024; Shenfeld et al., 2026)、reward variance 隱性正規化 (Lai et al., 2026)，或 weight-update 結構 (Lin et al., 2025; Zhu et al., 2025)。我們的工作是 *互補的*：我們檢視 *推理 SFT* 自身是如何跨領域與訓練資料、不同因素遷移的，並識別出在泛化上重要、但尚未被廣泛注意的因素。此外，與先前聚焦 forgetting 的工作不同，我們從 *預訓練的 base 模型* 開始，而非 instruction-tuned 模型——這能更好地把新獲得的泛化與既有能力的保留分開。

另一條獨立的工作線試圖修改 SFT 目標以改善泛化。一些研究透過 RL 或 distribution-matching 透鏡重新詮釋 SFT (Qin & Springenberg, 2025; Lv et al., 2026)，並提出替代的 weighting 策略 (Wu et al., 2026; Zhang et al., 2026; Li et al., 2026; Lin et al., 2026)。我們的工作是 *正交的*：我們保留 vanilla SFT 目標，並證明泛化不是這個目標的內在屬性，而是 *共同* 取決於 optimization 充足度、資料品質與結構，以及模型能力。

同時，數個工作研究 SFT 泛化的個別因子。Xie et al. (2025) 證明 memorization 與 generalization 在 fine-tuning 期間能共存。Lin et al. (2025) 在合成任務上發現 prompt diversity 能改善 SFT 泛化，雖然只在合成任務中得到驗證。Chandra et al. (2026) 揭示有錯誤 final answer 的 long-CoT 軌跡仍能改善推理表現。一個 concurrent 工作 (Kopiczko et al., 2026) 發現資料重複比 long-CoT SFT 中的單次 pass scaling 更優——這與我們的 §3.3 一致。Pipis et al. (2025) 證明在較小模型上 looping 比較常見，呼應我們在模型能力上的觀察。除了個別調查這些因子，我們系統性地變動 optimization、data、model capability，並把其他保持不變，描述它們如何 *共同* 形塑推理 SFT 的泛化。我們的對照設定也揭示新現象，例如跨領域效能的 dip-and-recovery 動態以及它對資料品質與模型能力的相依。

先前研究也顯示延長推理會引起 self-jailbreaking 與安全退化 (Yong & Bach, 2025; Mao et al., 2025)。相對地，我們從泛化的視角開始，並用 matched query 與 answer 的 CoT vs no-CoT 對照比較，因果上把安全下降歸因於 *程序模式*。

## 8. 結論與討論

在本研究中，我們證明推理 SFT 的跨領域泛化是 *條件式* 而非缺席：取決於 optimization 充足度、資料品質與結構，以及基底模型能力。Short-epoch 檢查點會低估最終的泛化 gain；經過驗證的 long-CoT 軌跡加上程序推理模式能產生更強的遷移；能力較強的模型比那些主要展示冗長詞彙的弱模型更能有效內化這些模式。這個泛化也是 *不對稱* 的：推理 gain 會持續伴隨 safety 退化。所以更具生產力的問題不是「推理 SFT *是否* 泛化？」而是「在 *什麼條件下* 它會泛化、付出 *什麼代價*？」更詳細的討論與限制見 App. A。

## 附錄 A. 討論與限制

**討論。** 我們的發現對於推理後訓練 (reasoning post-training) 點出兩個更廣泛的意涵。

第一，泛化對基底模型能力的強烈依賴 (Sec. 5) 顯示，應該更注意預訓練／中訓練 (mid-training) 資料與下游 SFT 資料之間的交互作用。在我們的實驗中，模型能力並不只是參數量的函數：規模相近但來自不同預訓練 pipeline 的模型（例如 Qwen3 vs. InternLM2.5）在相同的 SFT 資料與最佳化設定下，可能表現出不同的泛化軌跡。這意味著預訓練與中訓練期間獲得的知識與表徵會顯著塑造一個模型能從後訓練監督中提取出什麼，並且把基底模型當作一個固定起點來看，可能會掩蓋一個重要的設計選擇。

第二，我們的結果凸顯了模型、資料、演算法、訓練排程需要共同設計 (co-design) 的需求。沒有任何單一因子能孤立地決定泛化：強的基底模型在差的資料下仍會泛化失敗 (Sec. 4)、高品質資料在最佳化不足下會看起來無效 (Sec. 3)、弱模型在高品質資料上的延長訓練只產生邊際提升 (Sec. 5)。沒有普世最佳的資料 recipe、演算法或排程。最佳組態取決於其他元件。這種相互依賴使得「孤立 benchmarking 個別因子」的常見做法變得複雜，並暗示未來工作應該聯合探討這些因子。

**限制。** 我們的研究有數個限制。

(1) 我們專注於數學推理資料，因為數學問題容易驗證，且高品質的長 CoT 回應可以透過 rejection sampling 可靠地取得。我們的發現（特別是 dip-and-recovery 動態與跨領域遷移的條件）是否能延伸到其他推理領域（例如程式生成、科學推理、多模態任務），是未來工作的開放問題。

(2) 由於計算限制，我們的實驗在最多 20B 參數的 dense 模型上進行。我們尚未在更大的 dense 模型或在 mixture-of-experts (MoE) 架構上驗證結論，那些架構的最佳化動態與容量考量可能差異甚大。

(3) 我們不包含與 RL-based 方法的直接比較。雖然這種比較會很 informative，但我們的發現—— SFT 泛化條件式地依賴最佳化、資料與模型能力——意味著公平的比較難以建立：SFT 與 RL 的比較本身就可能隨這些因子改變，使得從任何單一實驗組態都難以得出普遍結論。

### B.1 資料集生成細節

我們的預設訓練資料集 **Math-CoT-20k** 包含 20,480 筆帶長 CoT 的數學推理範例。Query 從 OpenR1-Math-220k (Lozhkov et al., 2025) 的預設子集取樣，回應則由開啟 thinking 的 Qwen3-32B 生成。每個回應包含一個思考過程，後面接 step-by-step 的最終總結與答案。最大回應長度設為 16,384 token。生成參數依官方 Huggingface repo 的建議：temperature=0.6、top-p=0.95、top-k=20、min-p=0。我們對每個 query 生成多個回應，並用 math-verify (Hugging Face, 2024) 只保留答案正確的那些。對每個 query 我們只保留一個正確回應，若有多個正確則隨機選一個。

**Math-NoCoT-20k** 資料集直接由 Math-CoT-20k 衍生：移除 thinking 過程。**Countdown-CoT-20k** 從 Countdown-Tasks-3to4-Unique 取樣 20k 個 query，回應同樣由 Qwen3-32B 用上述參數生成。**NuminaMath-20k** 包含相同的 query，但回應來自 NuminaMath-1.5 資料集。

### B.3 評估細節

本節描述全文使用的評估設定。我們的目標是不只衡量領域內 gain，還要在一致的評估設定下衡量跨領域遷移、通用能力位移與安全側效應。

**評估框架。** 我們對 IFEval、HaluEval、TruthfulQA 與 MMLU-Pro 使用 lm-evaluation-harness (Gao et al., 2024)，對 LiveCodeBench v2 與 GPQA-Diamond 使用 Evalchemy (Raoof et al., 2025)。對數學 benchmark，我們用 math verify 驗證提取出的最終答案。我們在所有 benchmark 上標準化核心協議，並針對 benchmark 特定設定做調整以確保公平、可靠的評估。

**Benchmark 與評估設定。** 以下簡要介紹每個 benchmark，並描述評估超參數與指標：

- **MATH-500**：包含 500 道形式化數學推理與多步問題求解的精挑題目。對每題在 temperature 0.6 下生成 3 個回應，回報平均準確率 (avg@3)。
- **AIME24**：包含 30 道官方 AIME 2024 競賽級數學題。對每題在 temperature 0.6 下取樣 10 個回應，回報平均準確率 (avg@10)。
- **LiveCodeBench v2**：包含 511 道需要大量推理的程式題。對每題在 temperature 0.6 下取樣 3 個回應，回報平均準確率 (avg@3)。
- **GPQA Diamond**：包含 198 道由專家撰寫、研究所程度的科學推理與多步知識密集題。為了減少位置偏差，我們對每題隨機 shuffle 選項。在 temperature 0.6 下取樣 3 個回應，回報平均準確率 (avg@3)。
- **MMLU-Pro**：包含 12k 道知識密集推理題。我們從每個類別均勻取樣一個 1000 題的子集評估。在 temperature 0.6 下對每題取樣 1 個回應，回報準確率 (pass@1)。
- **IFEval**：包含 541 道指令遵循任務。評估為 rule-based。在 temperature 0.6 下對每個 prompt 取樣 1 個回應，回報平均 instruction-level strict accuracy。我們在評估回應時移除最後一個 `</think>` tag 之前的所有內容。
- **AlpacaEval 2.0**：評估開放式有用性與回應品質，共 805 個 user query。在 temperature 0.6 下對每個 prompt 取樣 1 個回應，回報來自 Llama-3.1-8B-Instruct-RM-RB2 獎勵模型（在 App. D 簡稱 RB2）的平均 reward score。我們在評估回應時移除最後一個 `</think>` tag 之前的所有內容。為確保評估的可靠性，我們額外採用兩個輔助獎勵模型：Skywork-Reward-V2-Llama-3.1-8B（簡稱 Sky）與 RM-Mistral-7B（簡稱 Mis）來為模型回應評分。結果見 App. D，呈現出一致的趨勢。
- **HaluEval**：評估幻覺行為與事實一致性。包含 Dialogue、QA、Summarization 三個子集（各 10000 個範例；共 30000）。為提高評估效率，我們從每個子集隨機取樣 1000 個範例，得到 3000 個範例的評估集。在 temperature 0.6 下對每個範例取樣 1 個回應，回報三個子集的平均準確率。
- **TruthfulQA**：在 TruthfulQA 上以開放式 QA 評估真實性，使用標準的 generation split（817 題）。我們使用官方的 TruthfulQA judge 模型 `allenai/truthfulqa-truth-judge-llama2-7B` 與 `allenai/truthfulqa-info-judge-llama2-7B` 分別評真實性與有用性。在 temperature 0.6 下對每題取樣 1 個回應，回報平均準確率。我們在評估回應時移除最後一個 `</think>` tag 之前的所有內容。
- **HEx-PHI**（Human-Extended Policy-Oriented Harmful Instruction Benchmark）：包含 300 道有害指令（30 個範例 × 10 個 Meta Llama-2 使用政策與 OpenAI 使用政策中所識別的禁止類別），用於 LLM 有害性評估。資料集可在 [此連結](https://huggingface.co/datasets/LLM-Tuning-Safety/HEx-PHI) 取得。依照原論文，我們用一個強模型（GPT-4.1）作為 judge model 對生成的回應給有害性分數（1–5）。分數 5 視為攻擊成功。在 temperature 0.6 下對每題取樣 1 個回應，回報平均 Attack Success Rate (ASR)。我們在評估回應時移除最後一個 `</think>` tag 之前的所有內容。

### C.6 案例研究：低能力模型 vs. 高能力模型

**Case I.** 如 Fig. 16 所示，這兩個回應處理同一道數論問題，卻在表層模式模仿與內化推理之間呈現明顯對比。**Qwen3-1.7B-Base step 640 回應**早早就識別出正確的候選集，卻從未鞏固結論。模型反而陷入長時間的回應 loop，重複「Let me check 17, 53, 71」幾十次而沒有邏輯進展，模仿「徹底驗證」的表層模式而沒有真正執行，直到 token 限制耗盡。**Qwen3-14B-Base step 640 回應**系統性地驗證每個候選，透過獨立方法交叉驗證，並收斂到 3 的乾淨最終答案。

這種對比表明較小的模型停留在「冗長回應期」，模仿審慎推理的形式，而較大的模型則內化了真正的推理模式。

### C.7 高能力模型在哪些 token 上學得更好？

在本節中，我們調查 Qwen3-14B-Base Step640 與 Qwen3-1.7B-Base Step640 在 Math-CoT-20k 訓練資料上的 token log 機率差異，提供一個直觀的視角看學習模式如何隨模型能力變化。

我們在同一組訓練回應上評估每個模型的 per-token log 機率。由於兩個模型都在相同的 (question, response) 上評分，log 機率差異純粹反映模型學到的分布，而非生成品質的差異。具體而言，我們從 MathCoT 訓練資料中隨機取樣 11 個回應長度超過 10,000 token 的範例，把回應長度當作問題難度的 proxy（假設 teacher 模型對難題會生成更長的推理軌跡）。

跨 11 個取樣回應（約 122K token），14B 在 89.2% 的所有 token 上指派更高的 log 機率（平均 log 機率 gap：14B 領先 +0.252）。這個 gap 並非均勻：當套用 ∆logprob > 1.0 的閾值時，14B 在 9.3% 的 token 上具有決定性優勢（11,305 token），而 1.7B 只在 1.2% 上有優勢（1,416 token）——比率是 8.0×。隨著閾值嚴格度增加，這個不對稱會放大：在 ∆logprob > 3.0 時，比率達到 18.7×。這顯示 14B 模型不僅是全面性地比訓練資料 fit 得稍微好一點，而是對某些類別的 token 展現出質性上不同的預測能力。

**圖 18：Qwen3-14B-Base Step640 相對於 Qwen3-1.7B-Base Step640 在 Math-CoT-20k 訓練回應上 log 機率優勢最大的 token 文字雲。**

為了識別哪些 token 驅動這個 gap，我們把每個 token 位置 map 到其近似的表層 word，並收集 14B 模型 log 機率超過 1.7B 超過 1.0 的 word，依出現頻率排名。如 Fig. 18 所示，產生的文字雲揭示一個鮮明模式：14B 模型最大的優勢集中在 **CoT 推理過渡詞**——*therefore*（233 次）、*alternatively*（91）、*maybe*（79）、*wait*（78）、*however*（44）、*think*（48）、*check*（65）。這些是模型在切換推理策略、自我修正、回溯或反思中間結果時的訊號詞——是 CoT 推理的結構骨幹。這顯示 1.7B 模型可以相當好地學習局部數學運算模式，但難以內化更高層次的「何時重新考慮、何時嘗試另一個方法、何時驗證」的流程。

第二大類 14B 領先的 token 涉及**數學領域術語**：*sqrt*（89）、*digits*（90）、*numbers*（85）、*sides*（86）、*polygons*（33）、*pentagon*（34）、*equation*（24）、*expression*（25），以及**邏輯推理動詞**：*compute*（43）、*remaining*（39）、*correct*（31）、*answer*（36）、*divisible*（20）。這些詞出現在數學推理的決策點，模型必須在 context 中正確調用特定概念或操作。相對地，1.7B 模型對任何詞類別都沒有對 14B 的淨優勢。扣掉重疊出現後，只剩下 7 個 1.7B 略勝 14B 的詞（例如 *simplified*、*algebra*、*intersections*），全部頻率只有 2–3，與雜訊難以區分。

Per-sample 分析進一步揭示這個 gap 是 problem-dependent：在一道偵探式邏輯推理問題（Sample 7，平均 ∆ = 0.443）與一道幾何切割問題（Sample 8，平均 ∆ = 0.436）上，14B 模型最為主導，而較簡單的代數問題顯示較小 gap（Sample 4，平均 ∆ = 0.158）。這強化了我們的詮釋：模型能力對需要持續連貫性與策略性自我監控的多步推理最為關鍵——這正是區分「思考」與「計算」的能力。
